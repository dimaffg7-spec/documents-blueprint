# 03. Типы документов: конфиг вместо кода

Один тип - это не «ещё один шаблон». Это связка:

```
тип = шаблон(ы) + активные секции формы + дефолты текстов
```

## Типы живут в конфиге, а не в коде

```yaml
doc_types:
  services:
    label: 'Договор возмездного оказания услуг'
    template: 'dogovor_services.docx'
    subject_default: '...'
    services_default: ['...', '...']
    form_sections: [subject, services_text, single_date, prepay, closing_doc]
```

Почему конфиг: список типов в коде означает, что каждый новый вид документа
идёт через программиста. В конфиге - через того, у кого есть эталон. Для
юриста, который сам себе заказчик и сам себе разработчик, это разница между
«сделаю вечером» и «когда-нибудь».

Добавление типа: раздел в yaml + шаблон .docx. Ветка в коде нужна только если
у типа принципиально другая логика сборки контекста, а это редкость.

## Секции формы: показать своё, спрятать чужое

У разных типов - разные поля. Договор на разовую услугу хочет одну дату,
договор на период - две. Форма показывает секции активного типа и прячет
остальные.

**Прятать нужно вместе с `disabled`. Это не стилистика, это баг.**

```js
node.style.display = on ? '' : 'none';
node.querySelectorAll('input, textarea, select')
    .forEach(el => { el.disabled = !on; });   // ← вот эта строка
```

Что происходит без неё: скрытое поле продолжает существовать в форме и
**отправляется на сервер**. Если в параллельных секциях есть поля с
одинаковыми именами (а они есть - это же одна и та же сущность в разных
режимах), значение из невидимой секции перебивает то, что оператор ввёл
в видимой.

Отладить это тяжело: на экране всё правильно, в документе - чужое значение.

Второй эффект того же: `required` внутри `display:none` **блокирует отправку
формы** молча. Браузер не может показать «заполните поле», которого не видно,
и просто ничего не делает по кнопке.

Правило короткое: **параллельные блоки с одинаковыми именами полей прячутся
только вместе с `disabled`**. Всегда.

## Варианты внутри типа

Бывает, что тип один, а тело чуть разное: например, закрытие актом или
универсальным передаточным документом - и это меняет структуру приложений.

Развилка:

- различие **в значении поля** → одно поле, один шаблон;
- различие **в структуре документа** → отдельный файл шаблона.

Не пытайся накрыть структурное различие условиями внутри .docx. Два файла
шаблона честнее и отлаживаются глазами; условие внутри документа не видит никто.

## Закрывающие документы

Акт, счёт, УПД собираются **из того же контекста**, что и договор: те же
стороны, тот же предмет, та же сумма плюс ссылка на основание.

Переиспользуй контекст, не собирай заново. Разойдутся - клиент получит акт
на сумму, которой нет в договоре, и это заметит его бухгалтерия.

Две особенности из практики:

- **В акте нет условий оплаты.** Акт фиксирует факт оказания услуг, а не
  порядок расчётов. Это канон почти всех реальных актов - не «забыли добавить».
- **У акта нет сквозного счётчика.** Акт один на договор, номер обычно «1».
  Дата акта часто оставляется прочерками - подписывают по факту.
