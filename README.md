# Documents Blueprint - конструктор документов под свою практику

Открытая методология плюс рабочий стартер: как одному человеку с AI-агентом
собрать **конструктор договоров, счетов и актов** под свои документы -
и перестать вбивать реквизиты руками.

Заполнил форму - скачал готовый `.docx` (или PDF со счётом и платёжным QR),
в котором тело документа осталось ровно таким, каким его согласовал юрист.

> **Где запускать.** Подойдёт любой AI-агент, умеющий читать файлы и выполнять
> команды: **Claude Code** (терминал, десктоп-приложение, веб), **Cursor**,
> **VS Code** с агентом, **Windsurf** и другие. «Чат» и «сессия» ниже - любое
> такое окно.

Это не «сгенерируй мне договор нейросетью». Это промышленный конвейер:
эталон → словарь полей → шаблон → форма → рендер → проверка, с чеклистами
и готовыми промптами на каждом шаге. Собран по опыту реальной эксплуатации.

> **Стек-агностик.** Стартер написан на Python (FastAPI + docxtpl), но
> методология переносится куда угодно: та же логика работает на Node, на PHP,
> внутри 1С или как кнопка в существующей CRM. Ценность здесь - порядок шагов
> и грабли, а не язык.

## Кому это

| Кто | Что автоматизирует |
|---|---|
| **Юрист, юрфирма** | договоры с клиентами, доп.соглашения, претензии, NDA |
| **Агентство** | договоры с подрядчиками, акты по проектам и промо-акциям, приложения |
| **ИП, малый бизнес** | договор + счёт + акт по каждой сделке, без бухгалтера |
| **Студия, подрядчик** | договор оказания услуг, спецификации, закрывающие |
| **Кто угодно с типовым документом** | любой документ, где меняются 10-20 полей, а тело одно |

Признак, что это твой случай: **ты открываешь прошлый документ, сохраняешь
копию и правишь в ней реквизиты**. Значит, у тебя уже есть шаблон - просто он
живёт в голове и в папке «Договоры_2025_финал_2».

---

## Что внутри

| Папка | Что это |
|---|---|
| **`docs/`** | Методология по слоям: конвейер, словарь полей, механика .docx, типы документов, счёт и нумерация, реквизиты, проверка, ПДн, встраивание в CRM, грабли |
| **`starter/`** | **Рабочий сервис**: форма → .docx/PDF, контрольные суммы реквизитов, распознавание карточки предприятия, нумерация, платёжный QR, тесты. Запускается одной командой |
| **`prompts/`** | Девять промптов для копипаста - по одному на каждый шаг конвейера |
| **`templates/`** | Бриф дня 0, пример словаря полей, план фаз |
| **`.claude/skills/document-factory/`** | Скилл для Claude Code - оркестратор всего конвейера |

## Быстрый старт - один промпт

Открой AI-агента **в пустой папке будущего проекта** и вставь:

```
Склонируй методологию documents-blueprint и веди меня по ней как персональный
инженер по документам.

1. Выполни: git clone https://github.com/dimaffg7-spec/documents-blueprint
   Затем прочитай documents-blueprint/README.md, все файлы в
   documents-blueprint/docs/ и documents-blueprint/prompts/, а также
   documents-blueprint/.claude/skills/document-factory/SKILL.md.
2. Дальше действуй как скилл document-factory: веди меня по конвейеру шаг за шагом.
3. Начни с дня 0 - БЕЗ КОДА. Расспроси меня:
   - какой документ я делаю руками чаще всего?
   - есть ли у меня РЕАЛЬНЫЙ подписанный эталон - и попроси его приложить;
   - откуда берутся данные: вбиваю руками, присылают карточку, лежат в CRM?
   - сколько человек этим пользуется?
4. Разбери эталон и собери со мной СЛОВАРЬ ПОЛЕЙ. Не пиши код, пока словарь
   не готов и я его не подтвердил.
5. Тело документа неприкосновенно: ты его не переписываешь и не «улучшаешь».
   Только подставляешь переменные поля.
6. Ничего не выдумывай: реквизиты, суммы, формулировки - только те, что я дал.
```

> Агент не умеет `git clone` - скачай репозиторий кнопкой **Code → Download
> ZIP**, распакуй в папку проекта и в пункте 1 замени клонирование на
> «прочитай файлы из папки documents-blueprint/».

## Быстрый старт - от рабочего кода

Нужен результат сегодня, а не методология:

```bash
cd starter && ./run.sh
```

Первый запуск сам создаст окружение, соберёт демо-шаблоны и откроет форму
на `http://127.0.0.1:8000`. Дальше подставляешь свой эталон по
[`docs/02-shablon-docx.md`](docs/02-shablon-docx.md).

## Как пользоваться - три уровня

**1. Просто читать.** Начни с
[`docs/00-pipeline-and-process.md`](docs/00-pipeline-and-process.md) - там весь
конвейер на один экран. Дальше по слоям.

**2. Копировать промпты.** Идёшь по проекту, на каждом шаге берёшь готовый
промпт из [`prompts/copy-paste-prompts.md`](prompts/copy-paste-prompts.md).

**3. Поставить скилл (Claude Code).** Скопируй
`.claude/skills/document-factory/` в свой `~/.claude/skills/` - агент сам
триггернётся на «автоматизируй мне договоры» и поведёт по конвейеру.

## Философия в одном экране

- **Подстановка, а не сочинение.** Тело документа прошло через юриста и через
  подписание. Меняются только переменные поля. Модель не пишет договор.
- **Эталон раньше формы.** Начинать с «какие поля нужны?» - значит выдумать
  форму, которая через месяц разойдётся с реальным документом.
- **Одно имя поля на всю систему.** Шаблон, форма, база, парсер, CRM. Разъедутся
  имена - каждое новое поле станет переименованием в пяти местах.
- **Готовые строки в шаблон.** Склонения, форматы, условия - в коде, где их
  видно и можно накрыть тестом. Логика внутри .docx не видна никому.
- **Контрольные суммы окупаются в первый день.** Опечатка в 20-значном счёте
  глазами не ловится, а цена ошибки - платёж, ушедший не туда.
- **Номер тратится после успеха.** Иначе каждый сбой оставляет дыру в
  нумерации, а объясняться придётся с бухгалтерией.
- **Документ - неизменяемая запись.** Реквизиты копируются снимком, ошибочный
  документ аннулируется, а не удаляется.
- **«Нет плейсхолдеров» ≠ «документ готов».** Шрифт и вёрстку ловит только
  глаз, и только в том формате, в котором документ уедет клиенту.
- **Методология живая.** После каждого проекта дописывай грабли обратно
  в [`docs/09-gotchas.md`](docs/09-gotchas.md).

## Дисклеймер

Материалы описывают **инженерную** сторону выпуска документов и не являются
юридической или бухгалтерской консультацией. Формулировки договоров, состав
обязательных реквизитов, порядок нумерации и требования к обработке
персональных данных сверяй с действующим законодательством и со своим юристом.

Все примеры реквизитов в репозитории **синтетические** (нули, «ООО «Ромашка»»)
и подобраны так, чтобы проходить контрольные суммы. Демо-шаблоны документов
написаны с нуля, юридической силы не имеют и годятся только для проверки, что
конвейер работает.
