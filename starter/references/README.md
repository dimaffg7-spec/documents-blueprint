# Сюда кладутся эталоны — твои реальные документы

Эта папка **в `.gitignore`**. Всё, что ты сюда положишь, останется на твоей
машине: в репозиторий не уедет и в чужие руки не попадёт.

Это не перестраховка. Эталон — реальный договор реальных сторон: там ФИО,
реквизиты, суммы и условия сделки. Такое не выкладывают даже «для примера».

## Что класть

```
references/
├── dogovor-uslugi.docx      ← твой подписанный договор
├── dogovor-postavka.docx    ← второй вид, если есть
└── akt.docx                 ← закрывающий
```

Два-три эталона одного вида лучше одного: сравнив их, сразу видно, что
меняется от сделки к сделке, а что держится неизменным.

## Как отдать эталон AI-агенту

`.docx` — это zip с XML внутри, не текст. Агент не прочитает его напрямую:
увидит бинарный мусор или откажется открывать. Сначала извлеки текст:

```bash
python read_etalon.py references/dogovor-uslugi.docx
```

Утилита печатает **пронумерованные абзацы** и отдельно **таблицы** (блок
реквизитов сторон почти всегда табличный, и половина переменных полей прячется
именно там). Номера абзацев — общий язык с агентом: «поле в абзаце 14»
однозначно, «там, где про оплату» — нет.

Сохранить в файл, чтобы приложить к чату:

```bash
python read_etalon.py references/dogovor-uslugi.docx > /tmp/etalon.txt
```

Дальше — промпт 1 из [`../../prompts/copy-paste-prompts.md`](../../prompts/copy-paste-prompts.md):
агент разбирает эталон и собирает с тобой словарь полей.

## Проверить готовый шаблон

Когда шаблон собран, посмотри, какие плейсхолдеры в него реально попали:

```bash
python read_etalon.py templates/dogovor_services.docx --placeholders
```

Список сверяется со словарём полей. Опечатка в имени (`customer_nmae`)
и плейсхолдер, забытый в колонтитуле, видны здесь сразу — а в готовом
документе первое даёт молчаливую пустоту, второе бросается в глаза клиенту.
