# Стартер: рабочий конструктор документов

Не демо-заглушка, а работающий сервис. Запускается одной командой, собирает
договор, акт и счёт с платёжным QR.

```bash
./run.sh
```

Первый запуск сам создаст окружение, поставит зависимости, соберёт демо-шаблоны
и поднимет форму на **http://127.0.0.1:8000**.

## Что уже работает

- форма с переключателем **типов документов** (типы описаны в конфиге, не в коде);
- **договор** `.docx` из шаблона: даты по-русски, суммы прописью, аванс и остаток;
- **счёт** в PDF с платёжным **QR по ГОСТ Р 56042**: код собирается
  автоматически из твоих реквизитов, клиент платит сканом из банк-приложения
  прямо на твой счёт (это перевод по реквизитам, не эквайринг);
- **акт** оказанных услуг из того же контекста;
- **распознавание карточки предприятия**: вставил текст - заполнились 10 полей;
- **контрольные суммы** ИНН, ОГРН, расчётного и корр. счёта по БИК;
- **база контрагентов** в markdown с поиском по названию и алиасам;
- **сквозная нумерация** `ГГГГММДДNNN` с механикой peek/commit;
- **проверка готового документа** перед выдачей;
- тесты на контрольные суммы и golden-тест контекста.

## Первые пять минут

1. **Задай свои реквизиты.** Они печатаются в каждом документе и зашиваются
   в платёжный QR каждого счёта, поэтому вводятся один раз и сразу проверяются
   контрольными суммами:
   ```bash
   .venv/bin/python setup.py
   ```
   Скрипт расспросит по полям и запишет `config/supplier.yaml`. Опечатку в ИНН
   или в расчётном счёте поймает на месте - другого шанса не будет, дальше это
   уедет во все документы сразу. Проверить уже заполненное - `setup.py --check`.

   Пока файла нет, сервис работает на примере с нулями и честно предупреждает
   об этом плашкой сверху.

2. **Заведи контрагентов** (по желанию):
   ```bash
   cp config/contractors.example.md config/contractors.md
   ```

3. **Прогони тесты:**
   ```bash
   .venv/bin/python tests/test_requisites.py
   .venv/bin/python tests/test_context_golden.py
   ```

4. **Собери документ** на форме и открой его в Word. Демо-шаблоны -
   заглушки без юридической силы; они нужны, чтобы убедиться, что конвейер
   работает целиком.

## Подставить свой документ

Главный шаг. Порядок - в [`../docs/02-shablon-docx.md`](../docs/02-shablon-docx.md).

**Куда класть свой договор:** в `references/` - папка в `.gitignore`, наружу
ничего не уедет. Там же лежит инструкция
[`references/README.md`](references/README.md).

**Как отдать его агенту:** `.docx` - zip с XML, агент не прочитает его напрямую.

```bash
python read_etalon.py references/moy-dogovor.docx        # текст с номерами абзацев
python read_etalon.py templates/moy.docx --placeholders  # проверить готовый шаблон
```

Коротко: свой эталон **не правится руками в Word**. Пишется скрипт, который
открывает эталон, находит абзацы по тексту и переписывает их целиком вместе
с плейсхолдерами, а в конце принудительно проставляет шрифт. Образец такого
скрипта - `build_demo_templates.py`.

Дальше добавляешь свой тип в `config/doc_types.yaml`: шаблон, заголовок,
дефолты, список активных секций формы.

## Что где лежит

| Файл | Ответственность |
|---|---|
| `app.py` | HTTP и только он: принял форму, позвал домен, отдал файл |
| `context.py` | форма → готовые строки документа (даты, суммы, состав услуг) |
| `requisites.py` | контрольные суммы, парсер карточки, база контрагентов |
| `numbering.py` | нумерация peek/commit |
| `render.py` | подстановка в .docx, конвертация в PDF |
| `invoice.py` | контекст счёта и платёжный QR |
| `validate.py` | проверка готового документа |
| `catalog.py` | чтение конфигов |
| `setup.py` | первичная настройка: реквизиты владельца + их проверка |
| `build_demo_templates.py` | сборка шаблонов из кода |
| `read_etalon.py` | .docx → текст для агента; проверка плейсхолдеров шаблона |
| `config/doc_types.yaml` | **типы документов - главный конфиг** |

Границы слоёв не случайны: вся «умная» логика в `context.py` - чистых функциях
без HTTP и без базы. Поэтому её накрывает golden-тест, и поэтому сервис можно
заменить на CLI, бота или кнопку в CRM, не переписав ни одной формулы.

## Требования

Python 3.9+. Для PDF - LibreOffice (`soffice`); без него сервис работает
и отдаёт `.docx`.

## Безопасность

Сервис слушает `127.0.0.1` - только эта машина. Внутри ходят персональные
данные и банковские реквизиты; наружу не уходит ничего: распознавание
и конвертация локальные.

В `.gitignore` уже закрыты `config/supplier.yaml`, `config/contractors.md`,
`data/`, `out/` и `references/`. **Проверь это до первого коммита** - убрать
файл из истории git на порядок сложнее, чем не коммитить его.

Подробнее - [`../docs/07-pdn-i-bezopasnost.md`](../docs/07-pdn-i-bezopasnost.md).
